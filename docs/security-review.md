# 보안 점검 (2026-11-16, v1.2.0)

서버 없이 기기 안에만 저장하는 앱이라, "남이 몰래 가져가는 길"과 "잘못된 파일이 앱을 망가뜨리는 길"을 중심으로 봤습니다.

## 고친 것

| 문제 | 정도 | 고친 방법 |
|---|---|---|
| 모양이 틀린 백업 파일을 가져오면 화면이 하얗게 멈추고, 저장까지 되어 다시 열어도 같음 | 중간 | 가져올 때 데이터 종류마다 칸을 하나하나 검사합니다(`src/data/validate.ts`). 꼭 필요한 칸이 틀린 기록은 빼고, 몇 개 뺐는지 알려줍니다. 같은 id는 처음 것만, 파일은 20MB까지. |
| 화면이 멈추면 설정에도 못 들어가 기록을 꺼낼 길이 없음 | 중간 | 비상 화면(`src/components/ErrorBoundary.tsx`): 다시 열기, 기록 꺼내기(백업 파일), 모두 지우기(두 번 확인). |
| 백업 파일의 사진·색 칸에 바깥 주소를 넣으면 그 주소로 요청이 나감 (열어 본 사실과 IP가 알려짐) | 낮음 | 사진은 기기 안의 그림(`data:image/...`)만, 색은 `#rrggbb`만 받습니다. 웹은 CSP로 바깥 그림도 막습니다. |
| 웹에 콘텐츠 보안 정책(CSP)이 없음 | 낮음 | 웹 빌드에 CSP를 넣었습니다(`vite.config.ts`). 이 사이트의 파일과 기기 안의 그림만 허용합니다. 배포용 빌드에서 화면이 막히지 않는 것을 확인했습니다. APK에는 넣지 않았습니다(Capacitor 연결 코드가 막힐 수 있어 폰에서 확인한 뒤에). |
| 앱에서 공유한 백업 파일(학생 정보)이 앱 임시 폴더에 쌓임 | 낮음 | 다음에 내보낼 때 지난 파일을 지웁니다. (방금 보낸 파일은 받는 앱이 나중에 읽을 수 있어 바로 지우지 않음) |
| 파일 공유 설정이 쓰지 않는 바깥 저장소 경로까지 열어 둠 | 참고 | `file_paths.xml`에서 `external-path`를 뺐습니다. |

## 알고 쓰셔야 할 것 (코드로 못 고침)

- **웹 주소의 기록은 같은 계정의 다른 GitHub Pages 사이트와 저장 공간을 나눠 씁니다.** 브라우저는 `leepillwoo.github.io` 전체를 한 곳으로 보기 때문에, 같은 주소 아래 다른 사이트에 나쁜 코드가 들어가면 이 앱의 기록(학생 이름, 보호자 번호, 사진)을 읽을 수 있습니다. **실제 학생 정보는 APK로 쓰시는 것을 권합니다.** 웹 주소는 둘러보기와 예시 데이터용으로 쓰세요. (고치려면 이 앱만의 도메인이 필요합니다)
- **디버그 APK**라서 폰의 잠금을 풀고 USB 디버깅을 켜면 컴퓨터로 앱 기록을 꺼낼 수 있습니다. 폰 잠금을 꼭 걸어 두세요.
- 백업 파일에는 학생 이름과 연락처가 그대로 들어 있습니다. 믿을 수 있는 곳(카카오톡 나에게, 내 드라이브)에만 보관하세요.

## 확인했고 문제없던 것

- 화면에 글자를 넣는 곳은 모두 React가 처리해 스크립트가 끼어들 수 없습니다. (`innerHTML`, `eval` 없음)
- 전화·문자 주소는 숫자와 `+`만 남기고, 문자 내용은 주소 규칙대로 감쌉니다.
- `__proto__` 같은 이름으로 앱 내부를 바꾸는 공격: 해당 없음 (깊은 합치기 없음)
- 사진은 기기에서 320px JPEG로 다시 그려 저장합니다. 원본 파일은 저장하지 않습니다.
- 안드로이드: 바깥에 열린 화면은 시작 화면 하나, 암호화 안 된 통신 허용 없음, 원격 주소(`server.url`) 없음.
- 실행할 때 바깥에서 불러오는 것 없음 (글꼴도 앱 안에 들어 있음)
- `npm audit`: 알려진 취약점 0개
- 공개 저장소 기록(커밋 전체): 지어낸 예시 번호(`010-0000-00xx`)뿐, 키·비밀번호·서명 키 없음
- GitHub Actions: 필요한 권한만(`contents: read`, `pages: write`, `id-token: write`)
